# Contributing

> **ARCHITECTURE / SCAFFOLD PHASE — PRODUCT FUNCTIONALITY NOT YET IMPLEMENTED**

Until Phase 1 is explicitly approved, contributions are limited to documentation, threat analysis, proposed contracts, non-executable schemas, and TODO-only placeholders.

## Design priorities

Apply these in order: privacy, security, user safety, simplicity, maintainability, accuracy, provider independence, cost control, scalability, feature breadth.

Every provider proposal must document purpose, permitted inputs, provenance, retention, terms, cost, failure modes, abuse cases, and a kill switch. New processing of personal data requires a data-flow update, threat review, retention decision, and legal/ToS review.

Use synthetic fixtures only. Never add real identifiers, captured provider responses, credentials, screenshots of personal dashboards, or production logs.

ADRs remain `Proposed` until explicitly approved. Implementation work must cite an approved backlog item and its acceptance criteria.
