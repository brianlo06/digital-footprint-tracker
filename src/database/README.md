# Database boundary

Phase 1 PostgreSQL access, Drizzle schema, tenant transactions, forced RLS, function-only maintenance/rate-limit/key-rewrap/provider-usage capabilities, and migrations live here and in `/drizzle`. The executable subset covers accounts, one identity, encrypted identifiers, verification, consent, audit, deletion receipts, pseudonymous rate-limit windows, synthetic provider usage reservations, and a breach-capability scan/provider-run/finding subset (`scans`, `provider_runs`, `breach_findings`, plain per-tenant RLS like `identifiers`/`consent_records`). The generic finding, observation, evidence, provider configuration, jobs, remediation, notifications, and suppression model remains conceptual in `docs/DATA_MODEL.md`.
