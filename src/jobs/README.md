# Job system boundary

The repository has three executable, separately deployable background tasks: the bounded retention Worker, the purpose-specific verification-delivery Worker, and the synthetic breach scan recovery Worker. Their committed configurations are route-less dry-build templates with placeholder bindings, not hosted deployments. Delivery and scan dispatch both ship fail-closed behind default-on kill switches; delivery still has only a synthetic no-op provider, while scan dispatch has only the zero-network synthetic breach adapter and a second default-off feature gate.

[ADR 0017](../../docs/adr/0017-verification-delivery-outbox.md) is accepted for local implementation and defines the delivery outbox's leases, retries, cancellation, least-privilege access, and deletion-race behavior. Provider selection, hosted activation, and the remaining activation evidence are still blocked.

The synthetic breach workflow has a separate, purpose-specific PostgreSQL `scan_jobs` state machine. The web mutation atomically queues only opaque account-owned UUID references, and Next.js `after()` accelerates one leased execution after the response. A once-per-minute route-less Cron Worker can reclaim a bounded due batch, including retry-delayed work and expired leases. Claims use a restricted security-definer transition; each job then receives its own transaction-local tenant RLS context before authorization and persistence. Retryable provider errors receive bounded exponential delay, processor crashes leave an expiring recoverable lease, one failed job does not block the remaining batch, and only unclaimed work can be cancelled. The Worker template is not deployed or active, no general-purpose queue exists, and live-provider orchestration remains unapproved.
